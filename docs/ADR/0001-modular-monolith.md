# ADR 0001：先采用模块化单体

## 状态

已接受。

## 决策

Banboos 2.0 第一阶段使用 FastAPI + worker + PostgreSQL/TimescaleDB 的模块化单体。领域、应用、契约和基础设施分层，API、Web、桌面和边缘端通过契约通信。只有在数据吞吐、故障隔离或团队边界达到明确阈值后，才拆分为独立服务。

## 原因

当前产品仍在从投资分析迁移到运营平台，领域边界和数据模型需要快速迭代。直接采用大量微服务会提高部署、观测、事务和版本兼容成本，且无法解决现场控制安全问题。

## 后果

需要提前维护清晰的包边界和契约测试；未来拆服务时可沿 `ingest`、`alarm`、`worker`、`report` 等边界迁移，而不改领域公式。
