Banboos 2.0 的 Web 端以 1.6.6 的功能语义为基线，复用同一套
Application 与 Domain 规则，不复制 PyQt 控件逻辑。旧版数据库只允许通过
隔离只读适配器读取。

## 对齐原则

1. Web 的每个按钮必须对应一个版本化 API 或异步任务，不能只做静态演示。
2. 实测、预设、仿真和历史回放在响应中明确标识来源模式；没有真实数据时返回空结果。
3. 日前和实时是唯一电价业务类型；`OK`、`missing` 只作为历史质量信息保留。
4. 财务联动使用节点有效数据的年度等权基准；不足完整年度时使用全部有效天数，
   并检查功率/容量时长关系，不锁死某个规模。
5. 每项能力先在 Web/API 契约测试中验证，再接入页面；生产控制继续保持关闭。

## 本轮交付

本轮新增年度价差基准的月度明细契约，节点分析展示每月有效日和连续窗口均价差；
同时保留 `GET /api/v1/price/curves` 的完整日 96 点曲线能力。所有接口在 demo 模式返回空结果，避免用模拟值冒充历史电价。

## 组合优化补齐（2026-09-16）

Web 已补齐桌面端组合优化的三种目标：预算内最大 NPV、预算内最大 IRR、达到年净现金流目标的最小投资。候选项目支持 1–50 项逐项录入，服务端使用 SciPy MILP 处理全部候选项，不再静默截断；最大 NPV 遵循桌面规则跳过非正 NPV 项目，并对无解/无可选结果返回明确状态。

每个组合结果包含投资、NPV、年净现金流、组合 IRR、算法版本和现金流口径说明；成功任务可下载 Excel，包含导出说明、任务参数、候选项目和选中项目。手工情景与真实节点收益分开标识，恢复任务时会从 `run_id` 重新加载参数和结果。
