# 1.6.6 桌面功能与 Web 对齐路线

Banboos 2.0 的 Web 端以 1.6.6 的功能语义为基线，复用同一套
Application 与 Domain 规则，不复制 PyQt 控件逻辑。旧版数据库只允许通过
隔离只读适配器读取。

## 功能基线

| 1.6.6 入口 | Web 入口 | 当前状态 | 下一步 |
| --- | --- | --- | --- |
| 连续均价差 | 节点分析 | 已有节点、日前/实时、真实日期范围、摘要与财务任务链路 | 增加月度连续窗口结果和来源快照 |
| 历史电价曲线 | 电价曲线 | 已新增完整日 96 点曲线 API | 接入曲线图、单日/月度/年度聚合和 PNG 导出 |
| 气象专题 | 气象专题 | 已有气象摘要 API和省级预设规则 | 增加光伏、风电功率仿真曲线及数据来源标识 |
| 财务经济性测算 | 测算任务 | 已有异步财务任务、现金流和 XLSX 下载 | 补齐全部模板参数、现金流明细、敏感性分析 |
| 组合优化 | 组合筛选 | 领域算法在服务端已有基础 | 增加项目编辑、预算目标、结果表和导出 |
| 省份资料图 | 省份资料 | 节点按省份读取 | 增加省份热力图、节点跳转和数据质量汇总 |
| 约束收益回放 | 调度回放 | 已有严格调度任务、快照和时长校验 | 增加逐日回放结果、曲线和失败原因展示 |
| 数据管理/日志 | 系统管理 | API 认证、就绪探针和请求追踪已具备 | 增加导入任务、数据库状态和审计查询 |

## 对齐原则

1. Web 的每个按钮必须对应一个版本化 API 或异步任务，不能只做静态演示。
2. 实测、预设、仿真和历史回放在响应中明确标识来源模式；没有真实数据时返回空结果。
3. 日前和实时是唯一电价业务类型；`OK`、`missing` 只作为历史质量信息保留。
4. 财务联动使用节点有效数据的年度等权基准；不足完整年度时使用全部有效天数，
   并检查功率/容量时长关系，不锁死某个规模。
5. 每项能力先在 Web/API 契约测试中验证，再接入页面；生产控制继续保持关闭。

## 本轮交付

本轮新增 `GET /api/v1/price/curves`，只返回最多 31 个完整的日 96 点曲线，
并把运营摘要接入总览页。曲线接口在 demo 模式返回空数组，避免用模拟值冒充历史电价。
