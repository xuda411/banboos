## 结论

本轮人工测试通过了主要用户路径和前端交互保护。八个主导航均可进入，登录方式切换、空数据提示、任务状态、财务结果、敏感性结果、权限角色、导入预览和报表下载均能正确反馈。财务测算和敏感性分析任务在服务进程恢复后均完成，导出的 Excel 文件可正常返回。

约束回放在当前 demo 数据上按设计失败，错误码为 `NO_VALID_PRICE_DAYS`，原因是演示库没有完整的 96 点有效电价日；页面正确展示失败状态，没有把空数据伪装成计算结果。原版 XLSM 模板复核返回 503，原因是当前隔离环境未配置模板文件，这属于发布前环境配置项。

## 发现与处理

### 已确认并在本轮恢复的运行问题

测试开始时系统盘和 E 盘存在重复的 API/Worker/静态服务进程，造成任务长期显示“排队中”。已停止重复进程并用 E 盘运行时重新启动 API、Worker 和 Web 服务；同样的财务与敏感性任务随后均完成。建议上线前将启动脚本改为单实例锁或 PID 检查，避免重复进程再次造成假性队列阻塞。

### 发布前需要处理的事项

1. **财务模板未配置。** `financial-template-reconciliation` 当前返回 HTTP 503，需在预发布/生产环境挂载并校验原版 XLSM 模板后再宣称模板单元格完全对齐。
2. **demo 数据没有完整有效日。** 曲线、调度、真实节点候选无法进行正向数值验证；需要准备包含至少一个完整 96 点有效日的脱敏测试夹具，再做一次正向回放和曲线截图验收。
3. **历史审计记录较多。** 系统审计表仍能看到早期遗留的排队任务。正式环境应增加 stale 任务回收、状态修复或时间范围筛选，避免误判当前运行状态。
4. **身份服务仍是开发联调模式。** 页面已展示手机号/邮箱/微信入口，但短信、邮件和正式租户授权仍需接入真实身份服务后进行上线验收。

## 发布判断

按本轮范围，前端交互、空数据保护、异步任务状态、财务与敏感性结果、权限展示和 XLSX 基础导出达到人工测试通过标准。项目还不能以“生产财务模板完全对齐、真实电价调度已验收”的状态直接发布；完成模板挂载、正向电价夹具、单实例服务治理和正式身份服务验收后，再进入上线候选版本测试。
