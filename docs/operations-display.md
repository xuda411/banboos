# 运营展示层与导航规划

Banboos2.0 的展示层参考 MYEMS 的公开产品组织方式：把数据采集、分析、报告和运营展示放在同一条工作流中，再按站点和权限扩展功能。参考项目公开说明见 [MyEMS GitHub](https://github.com/MyEMS/myems)。

本版先落地四个稳定入口：

1. **运营总览**：站点数量、有效电价日、数据点数、完整率、节点只读状态和系统脉搏；
2. **节点分析**：省份、节点、日前/实时和真实有效日期范围筛选；
3. **测算任务**：财务参数提交、异步进度和 XLSX 下载；
4. **边缘接入**：遥测批次、补传确认和网关心跳，生产控制保持关闭。

导航大屏采用“总览先行、分析和任务分流”的结构。实时运营指标优先放在首屏，详细参数放进工作台，避免把测算参数和运营状态混成一个页面。后续接入真实电站时，在总览下增加站点详情、告警中心、功率/SOC 趋势和报表中心，不改变现有 `/api/v1` 契约。

当前页面是无构建依赖的联调版，用于验证信息架构和 API 流程；正式上线前再迁移到 React + TypeScript，并保留相同的导航分组和权限边界。

## 运营摘要接口

总览页使用 `GET /api/v1/operations/summary` 获取一次性快照，避免前端把多个
列表接口的前几条记录误显示为系统总量。返回内容包括：

- `node_count`：当前配置运行时可见的节点数量；
- `task_counts`：任务按 `queued`、`running`、`succeeded`、`failed`、`cancelled`
  分组的数量及总量；
- `telemetry`：遥测总点数、待补传点数、已确认点数和待补传批次；
- `alerts`：告警总数、未确认/已确认数量和未确认的严重、警告数量。

接口只读且明确返回 `control_mode=disabled`。数据源不可用时返回 503，前端应显示
“暂不可用，稍后重试”，不能把异常降级成 0。响应使用 `scope=configured-runtime`
标记统计范围，后续接入租户和站点权限时再扩展范围字段。
