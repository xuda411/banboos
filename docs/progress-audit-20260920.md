审计日期：2026-09-20

## 结论

Banboos 2.0 已经具备真实数据只读联调、异步任务、节点价差分析、严格调度回放、财务测算、敏感性分析、投资组合优化、报表导出和迁移审计能力。当前 API 健康检查为 `ok`，就绪检查为 `ready`，联调数据模式为 `staging-readonly`，页面可见 10 个真实节点。

它还没有完整复现 1.6.6。最重要的差距不是页面数量，而是三个业务等价性问题：

1. 桌面 LP 优化与 Web 的投资组合筛选不是同一个模型；本次已新增独立 `lp-analysis` 任务完成逐日 LP 回放，组合优化仍保持独立。
2. 原始 xlsm 的财务规则更宽，包含单边效率、电量与 DOD、EOL 的日历/循环取小、增值税、保险费、固定运营费和收益分成；2.0 当前公式复核只保证服务器模型内部可重算。
3. 2.0 仍是只读/仿真联调版。没有租户权限、正式导入审批、PostgreSQL 全量生产迁移、现场设备协议和受控生产执行闭环。

因此当前定位是：**可用于 Web/API 联调、真实历史数据核查和人工验收；不等同于 1.6.6 生产替代版，也未开放真实电站控制。**

## 目前最需要修正的认知

“页面都有了”不等于“功能已对齐”。当前页面覆盖面已经接近完整工作台，但以下三项仍会造成业务判断差异：

- **LP 和组合优化必须拆开验收。** 组合优化选择项目，LP 优化决定单日充放电计划；两者输入、目标、约束和结果完全不同。
- **财务模板要先统一口径再追求外观。** 模板 D5 是单边效率，网页节点分析输入是往返效率；模板电量类还使用 DOD 和首年 EOL。没有口径转换层，复制模板样式反而会产生错误结果。
- **只读迁移不能直接称为上线。** 当前数据迁移和回放证据很强，但生产环境仍缺数据库权限、备份恢复、导入审批、并发任务、租户隔离和真实站点接入。

## 下一阶段建议

### P0：完成真正的 1.6.6 功能等价

1. **完成 LP 逐字段对账。** `lp-analysis` 已接入 2.0；下一步使用桌面固定样本逐日核对收益、充放电量、SOC、循环次数和窗口基准，并固定数值容差。
2. **继续完善财务口径转换层。** 单边效率、DOD、EOL 方案、运营费、保险、分成、增值税及附加、进项税结转和税前指标已接入，网页高级参数和敏感性参数已可提交；下一步补齐容量/辅助服务分阶段收益并逐单元格对账。
3. **完成 xlsm 对账。** 以原始模板副本为只读基准，对参数设定、电量类、容量类、辅助服务类、EOL、财务指标逐单元格提取公式和样式；先完成公式等价，再完成样式/宏/重算验证。原始模板不覆盖。

### P1：让真实节点分析成为可重复业务流程

1. 将价差分析结果一键保存为“投资情景”，保留节点、市场、完整年度窗口、2h/4h、效率、循环次数、利用率和保持率。
2. 从真实节点批量生成候选项目，接入组合优化；支持同一节点日前/实时分别比较，禁止混合市场。
3. 增加日/月/年聚合、缺日清单、重复来源清单、有效日/原始记录双口径展示和导出。
4. 气象接入公开省级预设，明确“预设/实测/预报/模拟”四种来源，补齐省级地图与光伏/风电功率曲线校准。

### P1：补齐上线基础设施

1. PostgreSQL + Alembic 全量迁移演练，包含恢复、回滚、索引和数据量/耗时报告；SQLite 仅保留离线 staging。
2. 加入租户/项目/电站/设备/测点权限模型，导出、导入、质量确认和任务查看分权。
3. 导入任务支持文件哈希、预览、字段映射、校验、审批、提交、失败回滚和审计日志。
4. Redis 多 Worker 并发、任务幂等、取消、重试、超时和结果保留策略完成压测。

### P2：进入运营而非仅分析

1. 完成设备协议适配和边缘网关现场验收，包含断网、补传、乱序、时钟、重复、联锁和回执。
2. 增加站点详情、SOC/功率/电量趋势、告警中心、日报/月报和运营大屏。
3. 调度分级开放：只读 → 建议 → 测试执行 → 生产执行；每一级均需审批、幂等键、有效期、回执和撤销。

## 建议的下一里程碑验收门槛

下一里程碑不要再以“页面完成”作为通过条件，应同时满足：

1. 桌面 LP 固定样本与 Web LP 逐日结果完全一致；
2. 财务模板关键单元格公式至少 95% 等价，其余差异逐项有映射和说明；
3. 真实节点批量导入可回滚，权限和审计记录完整；
4. PostgreSQL 恢复演练成功，任务在 API/Worker 重启后可恢复；
5. 关键网页流程在真实 staging 数据上通过，不再用 demo 模式作为主要证据；
6. 生产控制仍保持关闭，直到边缘联锁和硬件在环验收完成。

## 当前结论

2.0 已从“页面原型”进入“真实数据只读联调和可追溯分析平台”阶段。LP 历史分析已完成第一轮 Web 接入，下一步最有价值的投入顺序是 **LP 逐字段对账 → 财务模板口径/公式等价 → 导入与权限 → PostgreSQL/边缘运营**。继续堆叠页面不会缩小当前最大的功能风险。
