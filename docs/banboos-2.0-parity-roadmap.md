# Banboos 2.0 对齐与上线推进指导

更新日期：2026-09-29  
基线：Banboos 1.6.6  领域规则与人工验收基线  
当前代码：`976828d`  
开发目录：`E:\Banboos2.0`

## 1. 当前结论

Banboos 2.0 已经具备服务器化分析平台的主体能力：节点与电价查询、2 小时/4 小时连续价差、96 点曲线、LP/严格调度回放、财务任务、组合优化、气象展示、EMS 模拟、导出和系统门禁均已有代码与测试覆盖。

当前 E 盘全量测试结果为 **141 passed、3 warnings**。这证明代码链路可运行，但不能直接等同于桌面版 1.6.6 的业务等价或生产就绪。当前定位为：

> **Web/API 联调、真实历史数据回放和人工验收版本。**

尚未达到“完全替代 1.6.6 的生产财务工具”或“接入真实电站并执行控制”的条件。

## 2. 已形成的能力

1. **数据基础**：已将 1.6.6 全量节点数据导入隔离 staging，保留快照、哈希、质量记录和迁移批次。
2. **节点分析**：已实现日前/实时区分、完整年度优先、不足完整年度按全部有效日回退、2 小时/4 小时窗口和月度明细。
3. **曲线与导出**：已提供 96 点曲线、月/年聚合以及 CSV、Excel、PNG 导出。
4. **调度与 LP**：已支持异步 `strict-dispatch` 和 `lp-analysis` 回放、SOC/效率/循环约束、逐日结果、对账和 Excel 导出。
5. **财务链路**：已支持异步测算、融资、敏感性、现金流复核和结构化 Excel 输出，并保留 1.6.6 模板复核入口。
6. **运营基础**：已具备独立储能运行脉搏、遥测批次、告警、EMS 模拟接口、决策计划和反馈看板。
7. **部署基础**：已具备 FastAPI、Worker、Docker Compose、PostgreSQL/Redis 配置、健康检查、就绪探针和发布门禁。

## 4. 分阶段执行顺序

### 阶段 0：建立可重复对账基线（P0）

目标：让每个后续差异都有同一份输入、算法版本和输出证据。

- 固定 1.6.6 隔离数据库快照、模板版本和节点样本。
- 为日前/实时、2 小时/4 小时、完整年度/不足年度分别建立夹具。
- 输出桌面版与 2.0 的节点、价差、LP、财务、导出文件差异表。
- 将每次对账绑定 `snapshot_id`、`run_id`、算法版本和数据库哈希。

通过条件：关键样本能重复运行；差异能定位到输入、规则或输出单元格。

### 阶段 1：完成 1.6.6 核心业务等价（P0）

执行顺序：

1. 电价曲线聚合、缺日和重复来源展示。
2. 2 小时/4 小时价差逐字段回放。
3. LP/严格调度逐日轨迹、月度/年度汇总回放。
4. 财务参数、现金流、融资、税费和容量比例校验。
5. 原版 XLSM 公式、样式和 Excel/WPS 重算验证。
6. 组合优化真实节点候选自动生成和导出。

通过条件：核心样本业务数值对账通过；原版模板的已知差异均有记录，未知差异为零。

### 阶段 2：补齐气象和运营辅助能力（P1）

- 建立按省份的天气预设和来源标识。
- 补齐节点地理坐标、地图展示和天气驱动功率校准。
- 接入 EMS 只读遥测、告警、心跳、断线补传和回执状态。
- 运行脉搏只展示独立储能电站数据；模拟数据必须显式标注。

通过条件：模拟 EMS 与真实报文契约一致；实测、预计、仿真和历史回放不会混淆。

### 阶段 3：上线身份、租户和生产基础设施（P0/P1）

- 接入手机号、邮箱和微信身份服务。
- 完成验证码过期、重放、频控、会话撤销和越权测试。
- 将租户—集团—区域—项目—电站—设备权限落到 API 和数据查询。
- 完成 PostgreSQL、Redis、对象存储、备份恢复、监控和日志关联。
- 运行预发布环境，执行迁移、回滚、恢复和长任务故障演练。

通过条件：API token fallback 关闭；租户隔离从 `warn` 变为通过；预发布恢复演练成功。

### 阶段 4：受控执行评估（P2）

该阶段不自动开启生产控制，只进行资格评估：

- 数字孪生和 EMS 模拟长周期运行。
- 测试站和硬件在环验证功率、SOC、温度、通信和消防联锁。
- 指令审批、幂等、有效期、回执、撤销和审计全链路验证。
- 连续观察期内保持 `BANBOOS2_CONTROL_MODE=disabled`，任何失败都回退到只读/建议模式。

通过条件：负责人完成书面审批，所有控制门禁和现场联锁验收通过。

## 5. 每个阶段的统一交付物

每项功能必须同时提交：

1. 领域/应用代码和版本化 API 契约；
2. 自动化测试和真实/固定样本回放结果；
3. 页面人工验收记录和异常状态截图；
4. Excel/PNG 等导出物及哈希；
5. 数据来源、输入快照、算法版本和 `run_id`；
6. 已知差异、回滚方式和下一阶段入口。

## 6. 当前进度与下一步

阶段 0 已完成第一轮独立基线。24 个电价、迁移和 LP 样本通过，旧默认财务映射的 4 个样本出现可重复差异。阶段 1 已增加显式 `desktop_template` 规则模式，并在相同输入下完成 **28/28** 独立对账。

当前处于 **阶段 1 第 2 项：财务任务和 XLSM 导出接入兼容模式** 的交付验收阶段。`desktop_template` 保留 1.6.6 程序基线，`native_xlsm` 已通过固定样本的 360 项原生逐单元格复核，网页参数已经可以显式选择两种口径。本轮已增加可重复的 XLSM 发布门禁，并接入部署前检查：模板结构/样式、Excel 原生重算、缓存值、宏/数据表特征都会生成统一 JSON；生产环境只有在 `BANBOOS2_FINANCIAL_RELEASE_GATE=RELEASE_READY` 时才允许通过。当前门禁状态为 `PENDING_CROSS_ENGINE`，仅剩 WPS 或 LibreOffice 交叉重算。在原版模板完成跨引擎验收前，不扩展生产控制，也不把 demo 模式结果作为上线证据。

并行推进的阶段 3 身份基础已完成输入规范化、HMAC 标识哈希、脱敏、验证码频控策略和 `BANBOOS2_IDENTITY_HASH_SECRET` 生产门禁；短信、邮件、微信供应商适配、正式会话和数据库用户管理仍保持待接入状态。
