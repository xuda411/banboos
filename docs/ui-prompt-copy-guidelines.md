# Banboos 2.0 界面提示词规范

这份规范用于统一界面中的状态提示、错误提示、空状态和操作按钮文案。目标是让储能运营人员在不阅读技术文档的情况下知道：发生了什么、数据是否可信、下一步该做什么。

## 三层信息顺序

1. **结果**：先说当前状态，例如“接口可用”“计算完成”“暂不可用”。
2. **影响**：说明这是否影响当前操作，例如“本地模式不影响历史数据查询”。
3. **动作**：给出唯一的下一步，例如“检查日期范围后重新加载”。

页面不直接展示 `not-configured`、`422`、`run_id` 等内部值。需要追溯时，将技术细节放在导出记录、详情区域或开发日志中。

## 用词约定

| 场景 | 推荐文案 | 避免文案 |
| --- | --- | --- |
| 初始状态 | “选择节点和日期范围后加载” | “就绪”“等待查询” |
| 进行中 | “正在读取历史电价，预计需要几秒” | “处理中…” |
| 成功 | “已加载 12 个有效日，可查看曲线” | “OK”“完成” |
| 本地依赖未启用 | “未启用（本地模式），不影响当前查询” | “not-configured” |
| 失败 | “读取电价失败。请检查日期范围后重试。” | “API 422” |
| 权限不足 | “当前账号没有导出权限，请联系管理员申请。” | “Forbidden” |
| 无数据 | “该节点在所选日期没有有效记录。请更换节点或日期。” | “暂无数据” |

## 按钮命名

按钮使用“动词 + 对象”，让用户知道点击后会发生什么：

- `检查服务`、`刷新电价曲线`、`计算年度价差`、`导出 Excel`；
- 避免单独使用 `提交`、`确定`、`刷新状态` 等无法判断结果的词；
- 任务提交后按钮进入禁用状态，状态区明确显示“已进入队列”，不要重复显示“提交成功”。

## 错误与恢复

错误提示至少包含问题和恢复动作。对用户可处理的错误直接给出修复方向；对服务端错误只显示可理解的结果，并保留内部错误码用于日志追踪。提示颜色与文字必须同时表达状态，不能只依赖红色或绿色。

## 无数据与演示数据

历史价格、LP 回放和 EMS 模拟数据必须明确标注数据来源。模拟曲线使用“演示曲线，仅用于展示”提示，不得写成“实时运行”。
