## 结论

当前版本是“Web/API 联调、真实历史数据回放和人工验收版本”。可以部署到隔离的预发布云环境继续验证，但**不能直接接入公网生产，也不能接入真实电站控制链路**。

上线门槛必须从“页面能打开”改为以下链路全部可证明：

```text
用户/租户 → HTTPS/WAF → Web/API → 身份与权限 → PostgreSQL/Redis/对象存储
                                      ↓
                         Worker → 任务结果/导出/审计
                                      ↓
                         Edge → EMS 只读遥测/告警/回执
```

## P0 阻断项

### 1. 正式身份服务尚未接通

生产身份模式下，业务 API 会返回 `IDENTITY_AUTH_NOT_READY`；短信、邮箱、微信验证码接口当前也是契约占位，未实际发送验证码。生产前必须完成：供应商回调、验证码过期和重放防护、频控、会话撤销、设备/浏览器会话、用户与租户表、密码/密钥轮换、越权测试。

验收证据：真实供应商沙箱联调记录、登录/退出/撤销测试、跨租户访问返回 403、审计日志样本。上线前禁止使用 `development-open` 或 API token fallback。

### 2. 租户隔离尚未落到请求和查询边界

虽然 SQL 模型存在 `tenant_id`，但当前 API 的节点、任务、导出、审批和快照查询没有统一的当前租户上下文，也没有强制把租户条件下推到每个查询。`BANBOOS2_TENANT_ENFORCEMENT=strict` 目前会成为预发布门禁，不能用配置掩盖未实现的查询隔离。

验收证据：两租户夹具、同 ID 资源越权测试、任务/导出/归档/EMS 接口逐项 403 测试。

### 3. 生产数据源和本地文件不是云端事实库

`ReadonlyService` 仍以 staging/legacy SQLite 或 demo 模式工作；Docker 镜像没有复制隔离数据库，生产 Compose 只声明 PostgreSQL/Redis 容器，没有完成业务数据迁移、挂载或查询切换。组合审计、审批、边缘 spool、快照和归档仍有本地 SQLite/文件默认路径。API 和 Worker 也必须共享同一个数据/对象存储，而不是各自容器的临时文件系统。

验收证据：PostgreSQL 迁移版本、隔离 1.6.6 数据哈希、API/Worker 共享快照和任务结果、容器重启后数据仍可读。

### 4. Redis 队列不是可靠任务队列

当前生产队列使用 `BLPOP`；任务被取出后 Worker 崩溃会丢失队列消息。`recover_running()` 只能恢复状态，不能恢复已经从 Redis 列表弹出的原始任务。生产必须改为有确认、重试、死信和幂等的队列机制，或实现 processing list/ack/requeue，并测试 Worker 在领取、执行和完成各时点崩溃的结果。

验收证据：重复提交、Worker 强杀、Redis 重启、超时重试、死信和最终任务状态测试。

### 5. HTTPS、反向代理和公网边界缺失

生产 Compose 直接暴露 API 8000，没有 TLS 终止、WAF、限流、请求体限制、可信代理配置和域名健康检查；静态 Web 也没有纳入生产 Compose。必须使用云负载均衡或 Nginx/Caddy/Traefik，公网只开放 443，数据库/Redis/EMS 网关放在私网。

验收证据：HTTPS 强制跳转、证书自动续期、CORS 明确域名、健康/就绪探针、限流和访问日志关联 `X-Request-ID`。

### 6. 财务 XLSM 不能以服务器 Office 自动化作为默认生产链路

原版 1.6.6 XLSM 的 Excel 原生重算属于 Windows/Excel 环境能力，Docker Linux 镜像没有 Excel。当前发布门禁仍需 WPS/LibreOffice 交叉重算证据；“发现可执行文件”不等于“已经完成跨引擎重算”。生产应默认输出服务器生成的结构化 XLSX，原版 XLSM 作为受控离线/专用 Windows Worker 能力。微软明确不推荐或支持无人值守的服务器端 Office 自动化。[Microsoft 说明](https://support.microsoft.com/en-us/visio/considerations-for-server-side-automation-of-office)

验收证据：原版模板逐单元格对账、Excel/WPS/LibreOffice 独立重算报告、生成物哈希和人工抽检；未完成前发布门禁保持 `PENDING_CROSS_ENGINE`。

## P1 上线前必须完成

### 数据与数据库

1. 为 PostgreSQL 执行 Alembic 前进迁移，禁止应用启动时静默改表。
2. 建立节点、市场、质量、导入批次、快照、任务、导出、审批、EMS 遥测和审计表的 ER/索引/保留策略。
3. 1.6.6 隔离导入只追加，记录源文件哈希、迁移批次、字段映射、质量结果和回放版本。
4. 为时序遥测确定 TimescaleDB/分区表策略；PostgreSQL 只保存事务事实和索引。
5. 对象存储保存原始报文、导出物、快照和归档；数据库只保留元数据和哈希。

### 任务、导出和恢复

1. API 与 Worker 使用同一 PostgreSQL/Redis/对象存储配置。
2. 每个任务具备幂等键、进度、取消、超时、重试、失败原因和结果快照。
3. 导出文件采用临时文件 + 原子替换，下载链接短期有效并绑定租户/权限。
4. 归档 manifest 校验通过后才能标记“已归档”；归档状态与业务结果分离。
5. 完成 PostgreSQL、Redis、对象存储、审计库的备份与恢复演练，并记录 RPO/RTO。

### 观测与运维

1. 统一结构化日志：request_id、tenant_id、user_id、run_id、snapshot_id、gateway_id。
2. 指标至少包含 API 延迟/错误率、任务队列深度、任务耗时/失败率、数据库连接池、Redis 重试、导出耗时、EMS 延迟/在线率/补传率。
3. 配置错误、数据库不可用、队列积压、磁盘水位、证书到期和 EMS 断线必须告警。
4. 所有密钥进入云 Secret Manager；`.env` 不进入镜像、仓库或日志。
5. 发布使用不可变镜像、版本/迁移/配置哈希，支持一键回滚。

### EMS 与现场边界

1. 第一生产阶段仅开放独立储能 EMS 只读遥测、心跳、告警、历史补传和回执查询。
2. 模拟数据必须带 `source_mode=simulation`，不能和实测数据混入同一指标。
3. 现场网关不暴露公网，采用出站 mTLS；断网时本地缓存、去重、乱序和时钟校正必须可验证。
4. 调度建议与控制指令分离；`BANBOOS2_CONTROL_MODE=disabled` 持续保持，直到数字孪生、HIL、测试站和观察期全部通过。
